MuMuDVB - External transcoding with FFmpeg
==========================================
Originally by Meftah Tayeb; updated for current FFmpeg (ffserver removed)

Introduction
------------

Broadcast streams from terrestrial or satellite are often around 6 Mbit/s for
standard definition. When network bandwidth is limited, it can be useful to
transcode MuMuDVB outputs with an external tool such as FFmpeg.

Built-in MuMuDVB transcoding was removed. Use MuMuDVB to receive and demux the
transponder, then feed selected channels into FFmpeg (or another restreamer).

This tutorial assumes MuMuDVB is already streaming at least one channel over
multicast UDP or HTTP unicast. See `README.asciidoc` and `README_CONF.asciidoc`
for MuMuDVB setup.

Step 1: Configure MuMuDVB
-------------------------

Example (full autoconfiguration + HTTP unicast):

-------------------------
unicast=1
port_http=8080
freq=12476
pol=v
srate=27504
autoconfiguration=full
multicast_ttl=16
dvr_buffer_size=40
-------------------------

Start MuMuDVB:

--------------------------------------------------
mumudvb -d -c /path-to-config/mumudvb.conf
--------------------------------------------------

Confirm a channel is available, for example:

* Multicast: `udp://@239.100.0.0:1234`
* HTTP unicast by SID: `http://127.0.0.1:8080/bysid/123`

Step 2: Transcode with FFmpeg to HTTP (MPEG-TS)
-----------------------------------------------

FFmpeg can pull a MuMuDVB stream and publish a lower-bitrate TS over HTTP:

------------------------------------------------------------------------------------
ffmpeg -hide_banner -re \
  -i 'udp://@239.100.0.0:1234?fifo_size=1000000&overrun_nonfatal=1' \
  -map 0:v:0 -map 0:a:0 \
  -c:v libx264 -preset veryfast -b:v 1500k -maxrate 1500k -bufsize 3000k \
  -g 50 -keyint_min 50 -sc_threshold 0 \
  -c:a aac -b:a 128k -ac 2 \
  -f mpegts 'http://0.0.0.0:8090/channel01.ts?listen'
------------------------------------------------------------------------------------

Clients then open `http://server:8090/channel01.ts`.

Using HTTP unicast from MuMuDVB as the input instead:

------------------------------------------------------------------------------------
ffmpeg -hide_banner -re \
  -i 'http://127.0.0.1:8080/bysid/123' \
  -c:v libx264 -preset veryfast -b:v 1200k \
  -c:a aac -b:a 96k \
  -f mpegts 'http://0.0.0.0:8090/channel01.ts?listen'
------------------------------------------------------------------------------------

Step 3: Optional HLS output from FFmpeg
---------------------------------------

If you want FFmpeg-managed HLS (instead of MuMuDVB's built-in `hls=1` file mode):

------------------------------------------------------------------------------------
ffmpeg -hide_banner -re \
  -i 'udp://@239.100.0.0:1234?fifo_size=1000000&overrun_nonfatal=1' \
  -c:v libx264 -preset veryfast -b:v 1500k -g 48 -keyint_min 48 -sc_threshold 0 \
  -c:a aac -b:a 128k \
  -f hls -hls_time 6 -hls_list_size 5 -hls_flags delete_segments \
  /var/www/hls/channel01.m3u8
------------------------------------------------------------------------------------

Serve `/var/www/hls` with nginx or Apache.

MuMuDVB can also write HLS segments directly (`hls=1`); see the HLS section in
`README_CONF.asciidoc`.

Step 4: Optional SRT output
---------------------------

For contribution over unreliable links:

------------------------------------------------------------------------------------
ffmpeg -hide_banner -re \
  -i 'http://127.0.0.1:8080/bysid/123' \
  -c:v libx264 -preset veryfast -b:v 2000k \
  -c:a aac -b:a 128k \
  -f mpegts 'srt://0.0.0.0:9000?mode=listener'
------------------------------------------------------------------------------------

Run one FFmpeg process per channel you want to transcode. Use a process manager
(`systemd`, `supervisord`, etc.) for production.

Notes
-----

* Prefer pulling from MuMuDVB over localhost or a dedicated LAN segment so the
  original high-bitrate stream does not flood the client network.
* `-re` reads at native rate; omit it only if you know you need burst ingest.
* Codec and bitrate choices depend on your players and CPU budget; the examples
  above are starting points, not prescriptions.
* Historical `ffserver` workflows are obsolete (removed from FFmpeg). The old
  built-in MuMuDVB transcoder options under `doc/transcode/` are also obsolete.
